# Промпт: редизайн фронтенда OTP Secure

> Документ на согласование. Код пишем только после вашего «ок».
> Опирается на установленные скиллы: `emil-design-eng`, `apple-design`, `animate`, `choreograph`, `animation-performance`, `web-design-guidelines`, `mobile-native`, `break-ui`.

---

## 0. Роль

Ты senior frontend-разработчик и motion-дизайнер уровня Awwwards. Твоя задача — переосмыслить интерфейс OTP Secure так, чтобы он ощущался как продукт премиальной security-компании (Linear, Vercel, Stripe, Apple), а не как форма хакатона. Главный принцип: **сдержанность**. Красота здесь — в точности деталей, а не в количестве эффектов.

## 1. Что редизайним

| Страница | URL | Суть |
|---|---|---|
| Лендинг + демо | `/demo` | Главная витрина: hero, сам OTP-флоу, блок «как устроена защита» |
| Вход администратора | `/admin/dashboard` (без сессии) | Минимальная карточка ввода ключа |
| Security Dashboard | `/admin/dashboard` | KPI, живая лента событий, фильтр |

Бэкенд, API и логика **не меняются**. Все экраны OTP-флоу сохраняются: номер → код → успех / блокировка, а также состояния 401 / 410 / 423 / 429 / 503.

## 2. Жёсткие технические рамки (нарушать нельзя)

- **Vanilla HTML/CSS/JS**, без сборки, без React и Tailwind. Файлы: `app/templates/*.html`, `app/static/css/*.css`, `app/static/js/*.js`.
- **CSP `default-src 'self'`** уже включён: никаких CDN, inline-скриптов и inline-атрибутов `style=""`. Шрифт либо системный стек, либо self-hosted `.woff2` в `app/static/fonts/` (предлагаю **Inter Variable** или **Geist**, файл ~50–100 КБ).
- Анимируем **только `transform`, `opacity`, `filter` (blur ≤ 8px), `clip-path`**. Никаких анимаций `width/height/top/margin`.
- Фронтенд **никогда** не объявляет успех без HTTP 200 от `/otp/verify`. Таймеры только визуальные.
- Фронтенд не читает `outbox/sms.jsonl`. Остаётся лишь подсказка, где лежит код.
- `prefers-reduced-motion`: движения убираются, остаются только короткие fade.
- Hover-эффекты только внутри `@media (hover: hover) and (pointer: fine)`.
- Мобильная версия на ширине 360px без горизонтального скролла. Поля ввода шрифтом ≥ 16px (иначе iOS зумит страницу), `100dvh` вместо `100vh`, safe-area insets.

## 3. Визуальный язык

### Цвет — минималистичный градиент
- Основа: почти белый фон `#FAFAFB`, текст `#0A0A0B`, вторичный текст `#6B6B76`, границы `rgba(10,10,11,0.08)`.
- **Один акцент**: глубокий синий `#2F5BFF` → индиго `#6E56F8`. Градиент встречается **только в трёх местах**:
  1. Мягкое «свечение» в hero: одна размытая радиальная форма, opacity ≤ 0.35, медленно дрейфует (40–60 с цикл, `linear`, только `transform`).
  2. Основная кнопка: градиент едва заметен (2 оттенка одного тона, разница ≤ 8% по светлоте) и слегка сдвигается при hover.
  3. Прогресс-кольцо таймера OTP.
- Никаких радужных, неоновых и многоцветных градиентов. Нет glassmorphism ради эффекта: лёгкий `backdrop-filter` допустим только на шапке при скролле.
- Семантика: успех `#12A150`, предупреждение `#C27A00`, ошибка и блокировка `#E5484D`. Используются точечно, а не заливками экранов.
- Тёмная тема по `prefers-color-scheme` через те же CSS-токены (фон `#0B0B0E`, свечение мягче).

### Типографика
- Display-заголовок hero: 56–72px (clamp), `letter-spacing: -0.035em`, `font-weight: 600`, плотный leading 1.02.
- Текст 15–16px, leading 1.55. Моноширинный шрифт для цифр OTP, таймеров и псевдонимов (`tabular-nums`).
- Строгая шкала отступов на базе 4px. Много воздуха: hero занимает ≥ 80dvh.

### Детали, которые «складываются» (emil-design-eng)
- Концентрические радиусы: внешний радиус = внутренний + padding (карточка 20px → поле 12px при padding 8px).
- Тонкие тени из двух слоёв (contact + ambient), без жёстких чёрных теней.
- Фокус-кольцо: `outline` 2px акцентом + offset 2px, только по `:focus-visible`.
- `-webkit-tap-highlight-color: transparent`, `user-select: none` на кнопках, `touch-action: manipulation`.

## 4. Структура `/demo`

1. **Шапка**: логотип-знак (щит из одной линии) + «OTP Secure», ссылки API / Dashboard. Прозрачная, при скролле становится полупрозрачной с hairline-границей.
2. **Hero** (две колонки на десктопе, одна на мобильном):
   - слева: бейдж «INAI Hackathon 2026 · Task 6», заголовок «Одноразовые коды. Без единого шанса на перебор.», подзаголовок, две метрики-чипа («1 из 10⁶ · 5 попыток · 20/мин на IP»);
   - справа: **карточка OTP-флоу** — главный интерактивный объект страницы.
3. **«Как устроена защита»**: 6 компактных карточек-фактов (HMAC-SHA256, TTL 120 с, прогрессивные паузы 30/60/120, блокировка 15 мин, IP-лимит, атомарный Lua). Каждая с монохромной иконкой и одной строкой. Появляются при скролле одной группой.
4. **Мини-визуализация атаки** (декоративная, без запросов к API): строка из 20 «попыток», которые по очереди загораются и на 21-й упираются в «429». Объясняет защиту за 3 секунды. Запускается один раз при попадании во viewport.
5. **Футер**: одна строка, hairline сверху.

## 5. OTP-карточка: состояния и motion

Между экранами — **морф одной карточки**, а не смена страниц: высота карточки плавно подстраивается (через FLIP на `transform: scale`), контент делает crossfade с `blur(4px)` → `0`.

| Момент | Решение | Параметры |
|---|---|---|
| Номер → код | контент уходит влево (-12px, fade), новый входит справа (+12px) | 280ms, `cubic-bezier(0.23,1,0.32,1)`, выход быстрее входа (200ms) |
| Появление 6 полей | stagger, неравномерные задержки | 0 / 40 / 75 / 105 / 130 / 150 ms, `translateY(6px)` + fade |
| Ввод цифры | цифра «вплывает» в ячейку | `translateY(4px)` → 0, 160ms; рамка ячейки акцентная |
| Нажатие кнопки | press feedback | `scale(0.97)`, 140ms ease-out |
| Загрузка | текст кнопки → спиннер через blur-crossfade | ширина кнопки не прыгает |
| **401** неверный код | горизонтальная «встряска» ячеек | 3 затухающих колебания, 380ms, spring-подобный keyframe, красная рамка, затем очистка |
| **410** истёк | кольцо таймера гаснет, мягкий жёлтый inline-баннер | без движения ячеек |
| **423** блокировка | карточка морфит в экран блокировки: замок, обратный отсчёт 15:00 моноширинным шрифтом | кнопки визуально и реально disabled |
| **429** | inline-баннер с живым обратным отсчётом Retry-After | кнопка повторной отправки — кольцевой прогресс |
| **200** успех | единственная «праздничная» анимация: галочка рисуется (stroke-dashoffset), кольцо расходится один раз, лёгкий scale 0.96 → 1 | 600ms, проигрывается один раз; редкое событие, поэтому допустимо |
| Таймер 120 с | SVG-кольцо вокруг цифр времени, `linear`, последние 20 с — смена на warning-цвет | обновление раз в секунду, без дрожания цифр (`tabular-nums`) |

Правила: никаких `scale(0)`; ничего не анимируется на клавиатурный ввод, кроме мгновенной обратной связи ячейки; все переходы прерываемые (CSS transitions, не keyframes, где это возможно); на мобильных вставка кода из SMS через `autocomplete="one-time-code"`.

## 6. Hero-хореография (choreograph)

Одна сцена при загрузке, общая длительность ≤ 900ms, интерактивность доступна сразу:
1. 0ms — свечение фона fade-in (800ms).
2. 60ms — бейдж.
3. 120ms — заголовок построчно (маска `clip-path`, подъём на 100% высоты строки, 2 строки с шагом 70ms).
4. 260ms — подзаголовок и метрики.
5. 340ms — OTP-карточка: `translateY(12px) scale(0.98)` + fade, 500ms.

При `prefers-reduced-motion` — только общий fade 200ms.

## 7. Dashboard

- Сетка KPI: 5 карточек, цифры анимированно «докручиваются» только при **первой** загрузке (count-up 600ms); при автообновлении — мгновенно, а изменившаяся цифра коротко подсвечивается.
- Таблица событий: новые строки появляются сверху с fade + `translateY(-4px)` (только новые, не вся таблица); бейджи событий с точкой-индикатором severity.
- Фильтр — сегментированный контрол или select в стиле системы; кнопка «Обновить» с крутящейся иконкой во время запроса.
- Тот же визуальный язык, но **строже и быстрее**: рабочий инструмент, никакого декора, переходы ≤ 200ms.
- Логин: одна карточка по центру, поле ключа, лёгкое свечение фона как на `/demo`.

## 8. Доступность и качество

- Контраст текста ≥ 4.5:1, кнопок ≥ 3:1.
- Все интерактивные элементы доступны с клавиатуры; ячейки OTP — стрелки, Backspace, вставка 6 цифр; `aria-live` для статусов.
- Семантические элементы, `lang="ru"`, корректные `label`.
- Никаких layout shift при смене состояний (резерв места под баннеры).

## 9. Проверка готовности

1. Прогон по скиллу `web-design-guidelines` и исправление найденного.
2. `break-ui`: длинный номер, вставка «12 34 56», 0 событий в dashboard, 10 000 событий.
3. `review-animations`: все длительности и кривые из таблиц выше.
4. Визуальная проверка в браузере: десктоп 1440, планшет 768, мобильный 375; светлая и тёмная тема; reduced motion.
5. Полный цикл send → outbox → verify в UI, а также 401 / 410 / 423 / 429.
6. Существующие 57 тестов бэкенда остаются зелёными.

## 10. Вне рамок

- Новые API-эндпоинты, изменение бэкенда.
- Сторонние фреймворки и CDN.
- Звук, WebGL, 3D-сцены, курсор-эффекты: это шум для security-продукта.
