# OTP Secure — сервис одноразовых кодов (ТЗ № 6)

REST API выдаёт и проверяет 6-значные OTP: `POST /otp/send` и `POST /otp/verify`. Защита от перебора кода, SMS-спама и гонок при параллельных запросах. Состояние хранится в Redis.

Нужны только **Docker** и **Docker Compose v2** на Linux. Python, Redis и файл `.env` не нужны: все настройки и демо-ключи уже внутри `docker-compose.yml`.

---

## Запуск — скопируйте и выполните целиком

```bash
git clone https://github.com/KadyrovErjan/inai-OTP-claude.git
cd inai-OTP-claude
docker compose up -d --build --wait
curl -s http://127.0.0.1:8000/health; echo
```

Последняя строка должна вывести:

```
{"status":"ok","redis":"up","env":"development","outbox_enabled":true}
```

Всё запущено. Дальше все команды выполняются **из папки `inai-OTP-claude`**.

| Что | Где |
|---|---|
| API | `http://127.0.0.1:8000` — `/otp/send`, `/otp/verify` |
| Коды «SMS» | файл **`outbox/sms.jsonl`** в папке проекта |
| Демо-страница | http://127.0.0.1:8000/demo |
| Swagger | http://127.0.0.1:8000/docs |
| Панель безопасности | http://127.0.0.1:8000/admin/dashboard, ключ `inai2026-demo-admin-key-3e8b5d1f7a2c9064` |

Остановить: `docker compose down`. Остановить и стереть все лимиты и блокировки для чистого прогона: `docker compose down -v`.

## Проверка — скопируйте и выполните целиком (по желанию)

Блок проходит полный цикл и проверку двух IP. Выполнять **сразу после запуска**, иначе лимит IP уже может быть частично израсходован.

```bash
N="+996700123456"
otp() { grep "\"msisdn\":\"$1\"" outbox/sms.jsonl | tail -n 1 | sed 's/.*"code":"\([0-9]*\)".*/\1/'; }
post() { curl -s -o /dev/null -w "%{http_code}" "$@" -H "Content-Type: application/json"; }

echo "send:            $(post -X POST http://127.0.0.1:8000/otp/send -d "{\"msisdn\":\"$N\"}")   (ждём 200)"
CODE=$(otp "$N")
echo "verify:          $(post -X POST http://127.0.0.1:8000/otp/verify -d "{\"msisdn\":\"$N\",\"code\":\"$CODE\"}")   (ждём 200)"
echo "verify повтор:   $(post -X POST http://127.0.0.1:8000/otp/verify -d "{\"msisdn\":\"$N\",\"code\":\"$CODE\"}")   (ждём 410)"

printf "127.0.0.1 x19:   "
for i in $(seq 1 19); do printf "%s " "$(post --interface 127.0.0.1 -X POST http://127.0.0.1:8000/otp/verify -d '{"msisdn":"+996555000111","code":"123456"}')"; done
echo "  (ждём 410 x18, затем 429)"
echo "127.0.0.2:       $(post --interface 127.0.0.2 -X POST http://127.0.0.1:8000/otp/verify -d '{"msisdn":"+996555000111","code":"123456"}')   (ждём 410: у .2 свой счётчик)"
echo "127.0.0.1 + XFF: $(post --interface 127.0.0.1 -H 'X-Forwarded-For: 127.0.0.2' -X POST http://127.0.0.1:8000/otp/verify -d '{"msisdn":"+996555000111","code":"123456"}')   (ждём 429: заголовок игнорируется)"
```

Почему `410 x18`: лимит — 20 проверок за 60 секунд с одного IP по всем номерам, и два `verify` выше уже засчитаны. Через 60 секунд счётчик сбрасывается.

Атаки из ТЗ (перебор, 50 номеров, 100 параллельных проверок, два IP, 1000 попыток) запускаются одной командой:

```bash
docker compose exec api python attack.py
```

В конце выводится `OVERALL RESULT: PASS` или `FAIL`. Скрипт расходует лимиты, поэтому после него для ручных проверок перезапустите с чистым состоянием: `docker compose down -v && docker compose up -d --wait`.

## Ответы на три пункта уточнения жюри

| Пункт | Как сделано |
|---|---|
| **1. IP из подключения** | IP клиента — адрес TCP-соединения. Контейнеры работают в host-сети, NAT нет, поэтому `127.0.0.1` и `127.0.0.2` — разные клиенты. `X-Forwarded-For`, `X-Real-IP` и `Forwarded` не читаются. Адреса и номера в коде не прописаны. |
| **2. `advance: 120`** | Время **реальное**, нужно просто подождать. Срок жизни кода — TTL ключа в Redis. Режима подмены часов нет. |
| **3. Где взять OTP** | Файл **`outbox/sms.jsonl`** в папке проекта, одна строка JSON на каждую выдачу. Строка записывается на диск **до** ответа 200. |

### Формат `outbox/sms.jsonl`

```json
{"msisdn":"+996700123456","code":"048291","timestamp":"2026-11-20T12:00:00Z"}
```

* `msisdn` — номер в том виде, в каком он пришёл в `/otp/send`;
* `code` — 6 цифр, ведущие нули сохраняются;
* `timestamp` — время выдачи, UTC.

Строки разных номеров идут вперемешку, поэтому берите **последнюю строку своего номера**:

```bash
grep '"msisdn":"+996700123456"' outbox/sms.jsonl | tail -n 1
```

Строка появляется только при ответе 200. Действителен только последний выданный код номера.

## Интервалы (реальные секунды)

| Правило | Значение |
|---|---|
| Срок жизни OTP | 120 с с момента выдачи |
| Паузы между отправками на номер | 30 → 60 → 120 с |
| Отправок на номер | не более 3 за 600 с |
| Неверных кодов до блокировки | 5 (пятый сразу даёт 423) |
| Блокировка номера | 900 с; смена IP, новый код и перезапуск API её не снимают |
| Проверок с одного IP | 20 за 60 с, по всем номерам |

## Коды ответов

**`POST /otp/send`** — тело `{"msisdn": "+996700123456"}`. Варианты `+996700123456`, `996700123456`, `00996700123456`, `+996 700 123 456` считаются одним номером.

| Код | Когда |
|---|---|
| 200 | код выдан и записан в outbox |
| 429 | идёт пауза или исчерпан лимит 3 за 10 минут (`Retry-After`) |
| 423 | номер заблокирован после 5 неверных кодов |
| 422 | некорректный номер или тело |
| 503 | Redis или outbox недоступны (ложного 200 не бывает) |

Новая выдача отменяет предыдущий код номера: старый код после этого даёт 410.

**`POST /otp/verify`** — тело `{"msisdn": "+996700123456", "code": "048291"}`. Порядок проверок: лимит IP → блокировка номера → код.

| Код | Когда |
|---|---|
| 200 | код верный (ровно один раз) |
| 401 | неверный код |
| 410 | код истёк, уже использован, заменён новым или не выдавался |
| 423 | номер заблокирован; пятый неверный код сам возвращает 423 |
| 429 | больше 20 проверок за 60 с с этого IP (`Retry-After`) |
| 422 | `code` не из 6 цифр, некорректный номер или тело |
| 503 | Redis недоступен |

Повтор использованного или заменённого кода даёт 410 и не считается неверной попыткой. Сам код никогда не возвращается в HTTP-ответе.

## Как устроена защита

* **Генерация:** `secrets.randbelow(10**6)`, формат `06d`.
* **Хранение:** в Redis только HMAC-SHA256 от номера, id выдачи и кода; сравнение через `hmac.compare_digest()`. Ни кода, ни номера, ни IP в Redis нет.
* **Атомарность:** выдача, проверка и счётчики — Lua-скрипты Redis. Из 100 параллельных проверок верного кода успешна ровно одна.
* **Устойчивость:** лимиты и блокировки хранятся в Redis и переживают перезапуск API (`docker compose restart api`).
* **Журнал безопасности:** события без OTP, номеров и IP (только псевдонимы), панель `/admin/dashboard`.
* **Outbox** не отдаётся по HTTP и исключён из Git и Docker-образа.

Демо-ключи `ADMIN_API_KEY` и `OTP_HMAC_KEY` заданы в `docker-compose.yml` только для стенда хакатона. Для реального развёртывания их нужно заменить.

## Если что-то не работает

| Симптом | Решение |
|---|---|
| `address already in use` | занят порт 8000 или 6390: `API_PORT=8010 REDIS_PORT=6391 docker compose up -d --build --wait`, затем везде `8000` → `8010` (для `attack.py` добавьте `--target http://127.0.0.1:8010`) |
| `unknown flag: --wait` | старый Compose: выполните `docker compose up -d --build` и подождите 10 секунд |
| `/health` → `"redis":"down"` или 503 | `docker compose ps` и `docker compose logs redis` |
| `Permission denied` при чтении `outbox/sms.jsonl` | проект клонирован от `root`: читайте через `sudo` |
| у 127.0.0.1 и 127.0.0.2 общий лимит | запущен `docker-compose.desktop.yml` (вариант для Windows/macOS с NAT); на Linux используйте основной `docker compose up` |
| остались лимиты от прошлых прогонов | `docker compose down -v && docker compose up -d --wait` |

На Windows/macOS (Docker Desktop) используйте `docker compose -f docker-compose.desktop.yml up -d --build --wait`. Там всё работает, кроме различения 127.0.0.1 и 127.0.0.2: Docker делает NAT.
